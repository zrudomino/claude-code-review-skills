## Key Decisions Made
- **Codex default sandbox = danger-full-access** (user, 2026-11-08).
  - **Context**: the old keys were ignored, so Codex actually ran restricted. Options were keep-restricted / workspace-write / full.
  - **Rationale**: user wanted the original intent. Consequence: every call without its own sandbox flag (e.g. `codex exec review`, which takes none) runs with full access.
- **Discussion rounds read-only; execution workspace-write** (user).
  - **Context**: round 1 used workspace-write while the prompt said "do not modify code"; resumed rounds inherited full access (verified: a write succeeded without the override, was blocked with it).
  - **Rationale**: the sandbox now enforces what the prompt asks. Trade-off accepted: Codex can't run tests that write caches during discussion.
- **parallel.js: no shell + prompt on stdin** (user, over "no shell, prompt as arg").
  - **Rationale**: no cmd.exe interpretation of `& |`, paths with spaces work, no 32K command-line limit. `codex` resolves to a single `codex.exe`.
- **Resume usage = delta against previous `threadTotals`; fall back to raw if totals go down.**
  - **Rationale**: the parser can't see earlier rounds; the caller can. The fallback avoids negative usage if Codex ever stops reporting cumulative totals.
- **Tool budgets 8 / 3, discuss only; dispatch unbounded** (user).
  - **Rationale**: Codex warned budgets can hide review evidence; adversarial reviews via dispatch keep full freedom.
- **Web-tool off-switch deferred to item 2** (user).
  - **Rationale**: `-c web_search="disabled"` + docs MCP off is a half-measure (see Pitfalls).
- **No warm bridge yet.** Agreed with Codex: bounded prompt → remove unused tools → measure `tool_output_token_limit` + lean profile → bridge only as a latency experiment (a warm process saves no tokens).
- **node_repl MCP warning left as-is**: env vars come only from the Desktop app; `browser` + `computer-use` plugin hooks call `node_repl` `turn_ended`, so removing it would break them.
